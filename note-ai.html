2从 Chat 到「约束」：为什么你的 AI 答非所问

现场调研

多数同学只用过 Web Chat（豆包 / DeepSeek），没用过它们的本地软件。讲师提醒：有些困难任务网页端做不了，会逼你下载软件在本地开发。

一个最小例子

  • 问「Python 字典和列表有什么区别」→ 各家答案长度、侧重都不同 → 约束弱，回答不可控。
  • 加一句「希望可视化」→ 变成双栏布局对比图。
  • 再进阶「做一个 PPT/slides 阐释区别」→ 不再是纯文字，生成难度上来了。
💡 核心结论：LLM 只能输入输出文本。想做复杂任务，必须给它工具；想用好 Agent，必须再给它更多约束。约束多（如"已学完 SI100+、上下文有全部内容、要短答案、复习视角、不追求绝对严谨"）→ 结果明显更好（Grok 的例子）。

3AI 使用的四级阶梯（你处在哪一级？）

L1 Chat · 直接对话。简单问题首选（问 list/dict 区别、Linux 命令），不需读本地文件、无仓库限制、更快。 L2 Project / Workspace · 上传 Sources（40 个文件/整门课）建知识库，新对话仍引用，免重开上下文。网页端即可，无需下载。 L3 Coding Agent · Claude Code / Codex：读目录、改文件、跑命令、交付结果。大量本地文件交给它消化。 L4 API & Workflow · 接 API 把模型嵌进自己的系统（如自建客服）。需写代码按约定调用，拿结果回传。
何时用网页 Chat？简单、孤立问题；不想频繁读本地代码。
何时开 Project/Agent？文件多（10 录音+100 PPT）、需跨文件消化；Agent 用工具按需读文件名、只读感兴趣的部分。

⚠️ 陷阱：已经用上 Codex 的同学，容易"什么都用 Codex"。简单问题仍该回到网页 Chat——更快、无仓库负担。

4概念祛魅：LLM / Agent / 闭环 / MCP

结果不只取决于模型

同样一个任务，最终效果取决于这一层编排：上下文给了什么 → 工具能不能用 → Harness(Prompt) 与架构怎么设计 → 失败怎么重试 → 有没有证据验收。

Agent 闭环（细分四步）

步骤做什么为什么重要
① 读上下文收到目标先读上下文上下文长度有限，必须持续控制，别一次塞爆
② 选工具决定调用哪个工具工具可用性直接决定能力边界
③ 执行一步看结果跑一步，观察输出Evidence（证据）来自真实执行结果
④ 决定继续/回退/交人下一轮迭代或停Feedback Loop：把证据回灌 LLM 再迭代

概念辨析（高频考点）

概念定义 / 区别
LLM大语言模型，本质"高质量下一步预测器"：预训练（捂住下一个词让模型猜）+ 自回归生成 + Transformer。
Agent在 LLM 外补上工具/上下文/编排，变成"能完成任务的实体"。
Tool Calling / Function CallingAgent→LLM 这一层：LLM 推理完告诉 Agent "我要调哪个工具"。
MCPAgent→工具这一层：Agent 与具体工具沟通的协议（如网页搜索工具）。
Harness约束 Agent 行为的工程（Prompt 编排 + loop engineering + 架构）。简单带约束的 Prompt 即 harness，未必是复杂文件夹。
instruct / IT指令微调：让模型说话更符合人类偏好、像人话。
🧪 两个 Hands-on：① 让 GPT 生成"名字按字母序排序"的 Python 代码（推荐顺手下载 Codex）；② 多轮设计 + 联网搜索，把 Agent 完成过程截图。完成②说明你已进入 L3。

6工具链与选型细节

  • 自建网站/前端：用 Playwright（网页自动化最常用，默认下 Chromium；Windows 用本地 Edge 省一次下载）。告诉 AI 用它能用得更好。
  • SOTA = State of the Art（当下某领域之最）。软工 benchmark 看 DeepSWE：图越右上越好。
  • 模型例子：GPT-5.6 Sol（综合 73% 正确率 / $8.39，低耗 45%）；DeepSeek V4 Pro（~63% / 低开销，但当日宣布涨价、已不如 5.6）；Claude Opus 高耗上限高。
💰 中转站科普：上游订阅顶级会员（如 ChatGPT $200/月=20 倍额度，≈¥1000 买到 $16000 额度），再分发 token 盈利。Codex 无法登录可接第三方 API。几个同学合买 $200 方案比 $100（一周仅 50 次 Pro）划算。注意：ChatGPT 上下文 free/plus=272K，pro=400K。

⚠️ 中转站/第三方客户端会"降智"：GPT/Claude 不公开思维链（在云端加密），切模型或非官方客户端不认字段 → 智商可见下降；多个上下文注入（如"我叫 Kilo Code"+"我叫 Codex"）会让模型困惑。

7个性化与使用心法

  • Personalization：设 Style/Tone（高效简洁务实、减 Emoji、结构化）；关掉 FastAnswers（降质来源）；Codex 里放入所有项目，头脑风暴更契合。
  • 笔记模式语言风格：要求输出"随时可复制进 Obsidian"，别再转述一遍（讲师个人偏好，可借鉴）。
  • 任务预估：复杂探索 → 拉到 Pro 去干别的；要快 → High/Extra High；急事 → 手机语音（豆包）。很少用 Instant/Medium。
  • 细分需求自己开发：Hermes/OpenClaw 记忆理念好但用便宜模型上限低；大厂 Agent 架构已成熟，直接用大厂；长期个人管理类细分需求再自研。

8信息质量与学术诚信（重点）

放松检查 vs 严格验收

  • 有些事难做易查：设计"易检查的门槛"，就能放心让 Agent 一次搞定。例：Playwright 截图验证 UI 修复是否生效 → 形成"修复→截图验收"闭环。
  • 必须严收：你觉得"这东西很重要"时，自然严格检查。别对所有产出都人工兜底（AI 量大时你根本查不过来）。
🎓 学术诚信（大学红线）：区分三件事——
① 产品 vs 学术：ChatGPT 是好产品，但不是好"学术"——学术要明确定义问题、基于他人工作、有完整验收与实验。
② 课程作业 vs 个人项目：课程作业绝不用 AI 完成。一次外包 = 把整门课思考滚雪球式外包，恶性循环。
③ 产品思维（"ChatGPT 超厉害"）不要带进科研。

提升信息质量（两个维度）

产出：用 Markdown 而非 Word。Word 背后结构冗余难理解；文本模型对结构化文本接受度好（信院同学尤其）。
获取：去 X 关注 Anthropic AI 等一手源，别只从公众号梗图/夸张标题得知新模型。至少搞清：有哪些模态、上下文多大、这代侧重点、能干什么。

"保留思考"不是鸡汤——要拆成可执行方案：主动提升信息质量 + 保持敬畏，自然不丢思考。

9收尾与 Bonus

  • 生图彩蛋：有同学让 Agent 调工具写代码生成 SVG → 转 PNG（非直接生图），讲师点名表扬——这正是"给工具"的正确姿势。
  • Bonus（七夕）：用"星图"做完整项目：头脑风暴 → 收窄约束 → 上传哪些文件 → Agent 怎么自查迭代 → 交付什么产品。
  • 祛魅总结：不先背定义，从 Chat 逐步包出 Agent/Harness；细节（如 DeepSeek 不支持多模态）用脑子记、用中体会。配好任一 Agent 的自定义（如 DeepSeek 传图报错→想到它没视觉能力）。

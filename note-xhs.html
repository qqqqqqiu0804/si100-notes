PART 1
🔥 AI 不是搜索引擎，是「协作者」
很多人用 AI 的方式，从第一天就错了

你现在大概率在 L1：打开就问、复制答案。但真正会用的人是这样的——

  • L1 直接用：把 AI 当高级搜索引擎
  • L2 会写提示词 + 调工具：让它查资料、跑代码、读文件
  • L3 会搭 Agent / Harness：把 AI 套上约束和流程，自动干活
  • L4 闭环验收：不 blindly 信，自己验证每一步对不对
概念祛魅（记住这 5 个就够）：
LLM 本质=预测下一个字
Agent = LLM + 工具 + 循环
Tool Calling = 让 AI 调你的函数
MCP = 工具的统一接口规范（少写适配）
Harness = 给 Agent 套约束的壳子
「把 AI 当不可靠的协作者——
关键输出一律过你自己的确定性校验。」

还有个坑：别用某些「中转站」网页版查资料。因为思维链不公开，第三方客户端智商容易掉一截。学术诚信也别碰红线——能用 Markdown 就别死磕 Word，去一手源看别只看二手转述。

PART 2
🧱 抽象：计算机最底层的思维
看懂这一个词，你写代码会长脑子

定义：隐藏当前不需要关心的细节，只暴露完成任务要用的接口。细节没消失，只是「这层不用管它」。

  • GUI vs 命令行：都是对电脑的抽象，谁也不比谁高级。命令行擅长批量/组合/自动化。
  • 程序是什么：不是桌面图标。源码→解释器→字节码→进内存叫「进程」→CPU 跑机器指令。
  • 文件是什么：底层就是一串字节。按 UTF-8 解释=文本，按格式=图片/压缩包/EXE。改后缀名不改数据本身。
  • 环境 vs 依赖：依赖=要借的库（import 的东西）；环境=跑起来要的外部条件。所以才用 venv/uv 隔离。
「编程的过程，一边在用别人给的抽象，
一边在造自己的抽象。」
抽象会「漏」：出问题时底层会冒头——找不到模块（用错环境）、缺 DLL、打开的文件删不掉（句柄被占）。看懂报错=知道自己在哪一层。
PART 3
🧭 怎么学任何「陌生东西」
一个万能循环，套所有新框架/新语言/新项目

面对看不懂的东西，别慌，走这四步：

  • ① 定目标：要精细。「先让机器人动起来」比「学会 ROS2」好执行。
  • ② 建模型：它现在怎么工作？来源=已有知识 / 读文档(README、官方教程) / 搜+问 AI。模型一开始可以很粗糙。
  • ③ 试探：带着预测去操作。微小+可逆才是好试探；报错是好事，是系统给你新信息；重启能救急但不长知识。
  • ④ 验证：符合预期→模型成立；不符合→改模型，再循环。
学指针卡住？往下挖一层到「内存」：变量=一块内存，指针=存地址，*p=顺着地址找到那块。够解释问题就停，不用挖到晶体管。接陌生 GitHub 项目？先读 README→跑通 demo→顺着入口读，别被目录吓退。
PART 4
💡 真正拉开差距的，是心态
前面是「术」，这是「道」

配环境配两小时还在报错——你会有两种解释：

  • A：「这么简单都搞不定，我太菜」→ 焦虑、不敢碰
  • B：「真学到东西了」→ 下次愿碰更复杂的

同一个挫折，解释不同，学习轨迹就不同。高手和新手的差距，不是某次顿悟，是无数次微小积累。身边统计学最大因素就一个：投入时间。怎么让时间投得多？让学习本身「值得继续」——代码跑通那一下，成就感会滚雪球。

「乐观是一种不言自明的公理：
这里有个暂时不知道的原因，我能继续观察、搜索、试探。
哪怕今天没解决，也比开始多知道一些。」

别人基础好，别比「我差多少」，比「再积累一点会多会多少」。面对没见过的东西愿意搞明白，遇到问题知道一点点缩小范围——哪怕暂时不会，也别急着给自己下「我不行」的结论。
